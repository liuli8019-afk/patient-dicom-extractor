# 医院云影像 DICOM 自助提取（患者分享版 · Winning TCloud）

**免费、开源。你的检查影像，本来就该由你自己拿得到。**

不少医院的云影像分享链接（如卫宁健康 Winning TCloud 平台，上海胸科医院等医院在用）只给患者看渲染图，「下载原始 DICOM」按钮在患者分享版里被关掉了。于是有人收费代下，一次几十到几百元。这个仓库把完整方法公开：用你自己的分享链接和密码，把平台上的原始像素数据取回本地，封装成标准 DICOM 文件，可以导入 3D Slicer、RadiAnt、Horos 等阅片软件，也可以交给你的主治医生或异地会诊使用。

## 先说清三件事

1. **只能下你自己的。** 本方法只使用你本人收到的分享链接、你本人知道的密码、你本人授权的会话。不破解密码、不伪造身份、不碰别人的检查。用别人的链接下载别人的影像是违法的。
2. **拿到的是「像素零损失、DICOM 头本地重建」的文件，不是厂商原始文件。** 患者分享版在产品层面禁用了官方 DICOM 导出，本方法不去强行绕过那条被禁用的通道；而是通过查看器自身在用的像素接口取回平台保存的原始 16 位像素阵列（逐字节与平台数据一致，有校验方法），再在本地按 DICOM 标准重建文件头（UID、几何、窗宽窗位等来自平台元数据）。像素一分不少，但请如实向接收方说明文件来源，不要冒充厂商原始导出文件。
3. **影像是敏感医疗数据。** 下载结果只保存在你自己的电脑上，不要上传到网盘、社交平台或发给不明身份的人代处理。

## 你有哪几种用法

| 你是谁 | 用法 |
|---|---|
| 会用 AI 助手（Muse / 豆包 / ChatGPT 等带电脑操作能力的 Agent） | 把本仓库的 `SKILL.md` 发给它，并给它你的分享链接，按提示自己输入密码，其余由 Agent 按 SOP 执行并交付验证报告 |
| 会一点 Python | 直接用 `scripts/tcloud_dicom.py`，按 `SOP.md` 的步骤运行 |
| 都不会 | 把本仓库链接发给懂技术的家人/朋友，`SOP.md` 写的是完整流程，照着做即可。**不要把链接和密码发给收费代下的人**——他们用的就是同样的方法 |

## 成功长什么样

一次完整的提取交付应包含：

- 按序列分文件夹的 `.dcm` 文件（每层一个文件）；
- `instance_manifest.csv`（每层文件与平台 ImageUID 的对应关系）、`series_manifest.csv`、`sha256.csv`；
- `verification_report.json` 验证报告，且最终状态只能是 **完整 / 部分完成 / 未完成** 三者之一；
- 首/中/尾三张预览图，供你肉眼核对是不是你的检查、层数对不对。

缺验证报告的「下载好了」，不要信——包括不要信收费代下的。

## 适用范围与限制

- 适用：Winning Health TCloud 患者分享链接（`mIdentify.html?...` 形式），其他医院只要是同一平台一般同样适用；平台升级后接口可能变化，方法可能需要按 `SOP.md` 的思路重新核对。
- 不适用：医护/机构版账号（那本来就有官方导出，请用官方功能）；其他厂商的云影像平台（原理相通，但接口不同）。
- 链接有有效期，过期请回医院公众号/小程序重新获取分享链接。

## 文件说明

- `SOP.md` — 完整技术流程：入口结构、关键接口、签名规则、批量下载、本地封装、验证清单。
- `SKILL.md` — 给 AI Agent 的执行技能文件。
- `scripts/tcloud_dicom.py` — 参考实现（像素下载、DICOM 封装、完整性验证）。分享链接的解密密钥不在代码里写死，按 SOP §3 从平台自己的前端 JS 中还原——那本来就是发到你浏览器里的代码。
